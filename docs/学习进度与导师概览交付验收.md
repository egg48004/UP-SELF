## 本次完成

- 课程增加难度（Beginner / Intermediate / Advanced）和预计分钟数，管理员在创建/编辑课程时填写，学生卡片、详情、管理工作区展示。预计时间是参考，不是限时任务。
- 系统自动记住最后访问章节；进入课程时继续该章节，首页 Continue learning 回到最近访问的可用课程。尚无记录时不展示无效的继续链接。
- 学生主动 Mark as complete，可撤销为 Mark as not complete；打开章节或播放视频本身不算完成。状态持久化到 MySQL，刷新、退出登录和换浏览器后保留。
- 课程进度只统计当前已发布且未删除的章节。零章节显示0%，不错误显示100%。新增章节会改变分母；取消发布、删除的章节不计入。重新发布时保留已有真实完成状态。
- Learning history 是当前可访问的已完成章节列表，显示课程、章节、完成时间和打开入口，分页10条。撤销完成后从该列表移除；它不是不可修改的审计流水。时间显示为 Malaysia time。
- 导师 Student overview 每行对应“学生＋课程”，查看完成数/比例、已发布作业状态数量、最近共享心情等级和周，可搜索、分页并进入已有作业/心情页面。

## 权限与数据规则

学生仅能操作本人已加入且已发布课程中的已发布章节。请求不接受客户端指定记录所有者；其他学生、导师、管理员和maintenance不能代写学习记录。导师概览仅展示当前负责且已发布课程中的有效学生；转交导师、撤销选课、归档课程后，后续查询立即按当前关系过滤。

概览不返回作业正文、附件或私人备注；心情沿用同一首次告知版本，未确认或告知版本过期不展示记录。不进行风险评分、诊断、排名或连续学习惩罚。作业状态基于当前提交状态，草稿或未提交计入“not yet submitted”，归档作业不计入数量。心情是学生全局最近一条，不代表仅属于该课程，也不把旧周记录伪装成本周。

历史记录不会因为退出课程而物理删除，但失去访问时隐藏；重新加入可恢复。进度代表学生自报的章节完成情况，不等于观看时长或掌握程度。

## 直接体验

1. 用 `open-vscode.cmd` 打开生成的 `.local/up-self.code-workspace`。
2. 选择 **UP-SELF · Backend + Frontend**，按 F5。后端启动前自动运行 **UP-SELF prepare backend**：启动所需本地服务，并通过现有 Maven `process-resources` 准备 XML、SQL 等资源。不要同时运行 start.cmd 或第二份 Vite。
3. 浏览器打开 `http://127.0.0.1:5173/`。
4. 管理员：Course allocation → 建课/编辑 → Difficulty、Estimated learning time → 原有导师/学生分配和发布。
5. 学生：My courses → 打开课程 → 切换章节 → Mark as complete / Mark as not complete → 回首页 Continue learning → Learning history。
6. 导师：Student overview → 搜索学生或课程 → 查看学习、作业、心情汇总 → View course assignments / View mood history。

## 数据库与架构

新增 `V6__learning_progress.sql`，不改已执行的 V1～V5：

- `learning_course.difficulty`、`estimated_minutes`。旧课程默认 Beginner / 30 分钟，管理员应按真实课程调整，不是测得的课程时间。
