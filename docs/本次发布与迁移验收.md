## Git 发布与核对

准备提交的范围为上述源码、测试、交付截图、教程和实际迁移快照；构建缓存和本机生成配置继续被忽略。已有作业提交为 `c376ceb`；心情及本轮迁移整理将通过正常提交追加，保留历史，不使用 force push。

本次准备时受限执行账户无法写入项目 Git 索引，也无法读取 Windows 用户凭据库，因此提交与推送需在项目所属 Windows 用户的 VS Code PowerShell 执行。仅本地构建成功不能说明远端已更新，最终以命令成功输出及远端 SHA 为准：

```powershell
cd C:\Users\eggma\Desktop\codex\up-self
.\push-github.cmd
```

脚本确认 origin、fetch main、提交改动并正常 push。默认提交说明为 `Publish assignments, weekly mood and portable setup`。GitHub 要求登录时由本人完成。成功的最终依据是显示 `HEAD -> main`、`Push completed` 和新的提交号；没有这段成功输出就不能判定已上传。

推送后可在用户终端核对本地与远端主分支：

```powershell
git -c safe.directory="$PWD" rev-parse HEAD
git -c safe.directory="$PWD" ls-remote origin refs/heads/main
```

两个完整 SHA 应相同。新电脑再按教程选择完整 Restore 或空库 Init，不把 `git pull` 当成数据库实时同步。
