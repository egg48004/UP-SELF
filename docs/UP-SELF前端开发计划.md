## 3. 技术方案与版本状态

### 3.1 一套推荐方案 [建议]

Vue 3 SFC + Composition API + TypeScript；Vite构建；Vue Router；Pinia只存跨页面身份及偏好；Axios承担统一请求与上传进度；Element Plus作为唯一组件库，按需使用表格、表单、对话框、分页等；Vue I18n集中英文文案。普通CSS + CSS变量，不同时增加Tailwind、UnoCSS、Sass或第二UI库。原生HTML5媒体组件优先，不增加视频云、播放器SDK或转码服务。

工具：一个npm锁文件；ESLint和Prettier负责一致性；vue-tsc负责类型；Vitest + Vue Test Utils覆盖关键交互；Playwright覆盖跨角色闭环。测试工具是开发依赖，不增加线上服务。[Vue官方快速开始](https://vuejs.org/guide/quick-start.html)提供Vue工程入口；[Vue测试指南](https://vuejs.org/guide/scaling-up/testing.html)用于选择组件及端到端测试层次。这里采用的是项目规模下的组合建议，不宣称它是唯一工业标准。

### 5.1 BaseController与分页对齐 [缺口，P0]

参考项目有 `BaseController.startPage()`、`getDataTable(List<?>)`、`toAjax(...)`；`TableSupport.PAGE_NUM="current"`。`TableDataInfo`返回顶层`code/msg/rows/total`。独立项目目前账号和课程Controller直接调用PageHelper，接受`pageNum/pageSize`，未检索到独立BaseController/TableDataInfo实现。**不能在文档里把它写成已经封装。**

后续实施时按原标准在独立common模块迁移相关通用机制，统一列表Controller，英文msg；保留每页最多100的现有限制及权限过滤；不要复制交易审核等无关Redis方法。目标公开分页参数为`current/pageSize`。同一变更内更新现有静态页、Python验收脚本、API文档与Vue调用；必要时短期接受旧pageNum作为兼容别名，并明确优先current和移除条件。不能让前端长期对不同列表猜参数。

P0契约验收：准备超过一页的允许范围内数据，验证第1/2页、搜索归第1页、总数、越权过滤及最大页大小；getDataTable必须保留SQL分页得到的总数，不能先转普通List再用size冒充total。当前未分页的章节/资源/帖子小集合继续返回`data`数组，不能只在前端切页冒充服务端分页。

### 5.4 请求、会话与媒体

JSON响应先解析业务code，同时读取非2xx响应体。现有未认证出口可能是HTTP500 + code401，方法拒绝可能HTTP200 + code403。不能把两者统统当网络故障，也不能把HTTP200当操作成功。登录有顶层token，分页有顶层rows/total，详情有data，不能全局只return data。具体封装见准则第5节。

不复制开源模板的refreshToken队列：本后端没有该接口，JWT有效性由Redis会话检查，常规认证请求滑动续期；前端无权离线解码JWT推断可信角色或有效期。保留sessionStorage channel/token的当前行为，退出、换账号、401时清理身份、媒体链接和业务状态，401并发只提示/跳转一次。不要用后台轮询人为维持会话。

媒体使用POST access签发的短期相对URL。Vue中的video/img/track不能直接附Bearer头，使用ticket URL而不是JWT查询参数。每个视频和字幕分别取得ticket；请求需要真实206支持；图片失败有可读反馈。ticket到期可有限重取一次，权限撤销不能不断重试。持续播放不会因为媒体GET而续期登录态：长时间观看遇会话过期，应保存当前页面内的播放位置、提示重登，重新鉴权后由学生主动恢复；不把它当跨设备学习进度保存。实际浏览器需验证暂停后超过30分钟恢复、120分钟无认证请求和退出后再次请求的行为。

## 6. 开发、代理与部署衔接

建议前端目录 `up-self/frontend`；一个package.json与锁文件，不放进Java Maven reactor。开发时Java继续8080，Vite建议5173。前端统一`/api`请求前缀，Vite代理到8080并仅去掉`/api`，因此学生链仍是`/client/**`。媒体返回`/client/learning/media/...`时，使用统一URL解析器补`/api`，不要直接请求5173上的不存在路径。[Vite代理文档](https://vite.dev/config/server-options.html#server-proxy)

生产建议同域静态dist + 后端API和媒体路由转发；不以Vite开发服务器正式上线。前端使用hash路由可减少单机部署回退配置，后端返回的path形式媒体URL不受hash影响；这是小规模部署建议，确认后固定。节点只用于构建，服务器不强制长期运行Node进程。部署平台、费用和公网暴露不属于本轮，后续沿已有单机方式接入。

所有`VITE_*`都是可见构建配置，仅放API前缀等公开值；数据库、Redis、JWT签名密钥、初始密码绝不能复制进去。真实密码仍在现有本机后端配置，文档仅指向位置。
