# UP-SELF：跨电脑环境安装、首次启动与数据恢复

更新日期：2026-10-22。适用 Windows x64；项目可放在任意可写目录，不要求原用户名或桌面路径。未改变参考 Java 架构、依赖版本或业务功能。本轮尚未开发角色首页区分、作业或心情。

## 1. 仓库带了什么

- Java 六模块、Vue 前端、精确版本锁文件、启动脚本和文档。
- `config/application-local.yml`：当前真实数据库/Redis连接、JWT/TOTP密钥和初始账号密码，按所有者明确要求以明文跟踪。
- `migration/local-snapshot/up_self_dev.sql`：当前独立 MySQL 数据库的实际逻辑备份，包含 Flyway 历史、账号、角色、课程等；没有导出参考数据库。
- `migration/local-snapshot/uploads`：与该备份匹配的三个实际文件。
- `migration/local-snapshot/local-credentials.json`：当前本机 MySQL root、应用/迁移账号和 Redis 的真实凭据。
- `migration/local-snapshot/manifest.json`：快照生成时间和 SHA-256；不是持续自动同步。

不包含 JDK/Maven/Node/MySQL/Redis 安装包、`node_modules`、Maven缓存、MySQL物理数据目录或旧 Redis 登录会话。安装依赖后才能运行。仓库包含真实明文密钥，拥有仓库读取权限的人可以获取这些凭据。

## 3. 拉取与检测开发工具

先使用自己的 GitHub 账号获得该仓库读取权限，再运行：

```powershell
git clone https://github.com/egg48004/UP-SELF.git D:\projects\UP-SELF
cd D:\projects\UP-SELF
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\configure-local.ps1 -JavaHome "D:\dev\jdk1.8.0_231" -MavenHome "D:\dev\apache-maven-3.10.0" -NodeHome "D:\dev\node-v24.22.1-win-x64"
```

如果工具已在 PATH/JAVA_HOME 中，或者此电脑之前配置过，可以不传目录参数。脚本检查实际版本，不安装软件、不改系统 PATH。路径保存在忽略提交的 `.local/development-tools.json`；生成的 `.local/up-self.code-workspace` 记录这台电脑的具体安装路径。

共享根目录 `up-self.code-workspace` 是无固定用户名的模板。日常请用 `open-vscode.cmd` 打开生成工作区；不要复制另一台电脑生成的 `.local/development-tools.json` 或生成工作区。搬动项目或工具后重新运行配置脚本。

## 4. 准备 MySQL 和 Redis（二选一）

### A. 已有对应版本服务

确认 MySQL 监听 `127.0.0.1:3306`、Redis 监听 `127.0.0.1:6379`。Redis 密码应与 `config/application-local.yml` 一致，应用使用逻辑库 2。只使用独立 `up_self_dev`，不修改参考数据库。

MySQL root 密码不必与旧电脑相同：如果不同，自己准备一个实际的 MySQL客户端配置文件，后面传 `-RootClientFile`。脚本不会重置已有 root 密码。不要对正在使用的数据库实例执行下述“全新初始化”。

### B. 新电脑使用 ZIP 版独立本地服务

解压 MySQL 与 Redis，然后仅生成本项目的新服务配置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\configure-services.ps1 -MySqlHome "D:\dev\mysql-5.7.44-winx64" -RedisHome "D:\dev\Redis-x64-5.0.14.1"
```

脚本生成 `.local/my.ini`、`.local/redis.conf` 和本机服务路径，Redis 密码直接取实际快照；配置与原本机一致地只监听本机。不会初始化/覆盖数据库，也不会启动服务器。`.local/mysql-data` 尚不存在时，**只在新电脑、全新数据目录**执行：

```powershell
& "D:\dev\mysql-5.7.44-winx64\bin\mysqld.exe" "--defaults-file=$PWD\.local\my.ini" --initialize --console
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\services.ps1
& "D:\dev\mysql-5.7.44-winx64\bin\mysql.exe" -h 127.0.0.1 -u root -p --connect-expired-password
```

第一条命令会显示新 MySQL 的临时 root 密码，用它完成第三条命令的登录。进入 MySQL 后把临时密码改为你要使用的真实密码；若要直接复用快照，填写 `migration/local-snapshot/local-credentials.json` 中 `mysql_root_password` 的实际值。例如 SQL 语法为 `ALTER USER 'root'@'localhost' IDENTIFIED BY '在此填入实际值';`，再 `exit`。不要把这条操作用于原电脑已有 root 账号。

新服务的物理数据在本项目 `.local/mysql-data`、`.local/redis-data`，不会提交。以后重启电脑运行 `scripts/services.ps1` 即可后台启动，或使用 VS Code 的数据库/Redis任务。原电脑继续使用原有服务目录，本轮没有重新初始化或迁移原实例。

## 5. 选择首次空库启动，或恢复当前数据

两条流程只选一条；不要先让后端生成表，再往已有表里导入完整备份。

### 路线一：干净的新开发库

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\database.ps1 -Action Init -MySqlHome "D:\dev\mysql-5.7.44-winx64"
```

脚本创建空 `up_self_dev`，按原模式建立应用 DML 用户与 Flyway 迁移用户。然后首次启动后端时，Flyway 自动执行 V1～V3，程序在用户表为空且 bootstrap 开启时建立四个初始账号。这里不会出现旧电脑的课程和媒体记录。

### 路线二：恢复当前实际内容（本次迁移推荐）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\database.ps1 -Action Restore -MySqlHome "D:\dev\mysql-5.7.44-winx64"
```

脚本先验证快照文件 SHA-256，拒绝非空目标数据库或非空上传目录，再导入数据库并把匹配媒体复制到 `.local/uploads`。恢复账号密码哈希、课程记录及 Flyway V1～V3历史；不会清空重建或重置已有 root。

默认使用快照中真实 root 密码连接。如果新电脑的 root 密码不同，复制自己的 MySQL客户端配置文件，保存 `[client]` 下的 user、password、host=127.0.0.1、port=3306、protocol=tcp，再追加 `-RootClientFile "D:\private\mysql-root-client.cnf"`。命令行无需写密码。已有同名应用用户若使用不同密码，CREATE USER IF NOT EXISTS 不会替你重置它；请使用干净独立实例或先明确整理该账号。

脚本默认 `Check` 只读检查连接与表数：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\database.ps1 -Action Check -MySqlHome "D:\dev\mysql-5.7.44-winx64"
```

`-DatabaseName` 仅允许 `up_self_` 前缀的独立库；普通迁移保持默认 `up_self_dev`。`SkipAccountSetup/SkipUploads` 只供隔离验收，不用于正常完整迁移。

## 6. 安装依赖、构建和运行

```powershell
.\frontend.cmd install
.\build.cmd
.\open-vscode.cmd
```

首轮下载 Maven/npm依赖需要网络。不要复制旧 `node_modules` 或在 package-lock 外执行随意升级。Java构建使用项目本地 `.local/maven-repository`；不再固定旧电脑的仓库绝对路径。

在生成工作区中：

1. 运行任务 **UP-SELF: 启动数据库与Redis**。
2. 选择 **UP-SELF · Backend + Frontend**，按 F5。
3. 等待 Java 的 `Started UpSelfApplication` 和 Vite 的启动信息。
4. 打开 `http://127.0.0.1:5173/`，不要把 8080 根页当新 Vue界面。

也可用两个终端：第一个运行 `.\start.cmd` 启动后端，第二个运行 `.\frontend.cmd dev`。不要同时用 F5 和 start.cmd 启动同一后端。

初始登录用户名：student01、mentor01、admin01；maintenance保留内部维护。密码位于 `config/application-local.yml` 的 `bootstrap.passwords`。完整备份恢复后，数据库里已修改过的密码以数据库为准，bootstrap不会覆盖它。Redis不搬旧会话，重新登录即可。

## 7. Flyway在新电脑的行为

每次启动**Java后端**都会检查迁移；前端启动不执行迁移。空库执行 V1～V3，已经恢复完整历史的库不会重跑它们；将来新增 V4，启动时执行尚未应用的 V4。旧脚本被改动时可能校验失败。

Flyway已配置 `baseline-on-migrate: true`。不要手工创建部分业务表再首次启动，以免旧版本被当作基线跳过。不要删除历史表来强迫重跑。完整恢复必须同时保留业务数据和历史表。数据库同名不会让两台电脑自动同步。[Spring Boot 2.5.14说明](https://docs.spring.io/spring-boot/docs/2.5.14/reference/html/howto.html#howto.data-initialization.migration-tool.flyway)

## 9. 常见问题

| 现象 | 检查 |
|---|---|
| 找不到Java/Maven/Node | 重跑 configure-local.ps1 并传实际安装目录；指定安装目录，不是 bin目录 |
| F5找不到Node | 使用 open-vscode.cmd 打开 `.local` 中生成的工作区，不复制另一台电脑生成文件 |
| 数据库Access denied | 核对实际root客户端配置、app/migration用户与权限；不会通过重置原 root来解决 |
| Restore拒绝非空库 | 这是保护行为；保留已有数据，另用干净独立库/新克隆，不删Flyway历史表 |
| Redis NOAUTH/WRONGPASS | 核对正在运行实例的密码与 application-local.yml；不要连接参考 Redis |
| 端口占用 | 先确认已有进程用途，不盲目杀进程；仅启动一套前后端 |
| 有课程但图片/视频失败 | 同时恢复匹配的 `.local/uploads`，核对manifest；数据库备份不包含视频字节 |
| Git dubious ownership | 使用本项目 push-github.cmd；脚本仅单次信任确切项目路径，不设置全局 `*` |

后续新增课程/作业后，需要重新生成相互匹配的数据库和文件快照；本次快照不会自动变成最新。公开期间已暴露的凭据不会因改为私有而自动失效。
