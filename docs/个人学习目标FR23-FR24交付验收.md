# 个人学习目标 FR-23、FR-24 交付与验收

日期：2026-10-23。独立项目：UP-SELF。仅实现个人学习目标，不开发收藏、统计、群聊、AI或其他FR。

## 1. 范围和实际规则

- FR-23：学生创建个人学习目标，输入标题和可选备注，保存到MySQL。
- FR-24：学生编辑、标记完成和管理目标；按本轮明确要求支持确认后删除。完成状态可以恢复为Active，便于纠正误操作，仍属于同一个管理功能。
- 标题必填，最多150字符；备注可选，最多2000字符。目标为Active或Completed，不要求截止日期或关联课程。
- 目标仅本人可见，包括备注。导师、管理员、内部维护没有个人目标管理入口，不能通过接口读取学生目标。与导师可读的共享心情采用不同的业务权限。
- 创建时间、更新时间、完成时间由服务端保存。编辑完成目标保留完成状态；重复完成不改变原完成时间；恢复Active清除完成时间。
- 删除是永久删除，页面先确认；不删除课程、作业或学习历史。没有增加目标历史、附件或奖励系统。

报告原文FR-23为创建个人学习目标，FR-24为更新、编辑或完成目标（PDF第33页）。原报告未单列删除操作，本轮按用户确认将删除纳入FR-24的管理范围，不新增FR编号。当前61个FR合计更新为**21完成、6部分、34未完成**；其他条目状态保持原口径。

## 2. 学生如何使用

1. 用`open-vscode.cmd`打开工作区，选择`UP-SELF · Backend + Frontend`按F5。
2. 访问`http://127.0.0.1:5173/`，选择Student登录。已有会话请退出后重新登录，获取V7新增权限。
3. 导航进入 **My goals** → **Create goal**，填写 **My next step** 和 **Notes (optional)** → **Save**。
4. 每条目标提供 **Mark as complete / Mark as active**、**Edit goal**、**Delete goal**。
5. **Show goals**筛选All goals、Active或Completed；**Refresh goals**重新读取；超过10条可分页。
6. 编辑或删除遇到并发冲突时不会覆盖其他页面的修改；取消编辑后点击Refresh goals获取最新版本再操作。失败的编辑保留输入，便于复制或修正。

英文短句、文字配图标、状态不只依靠颜色；备注以纯文本显示。使用现有字号/高对比/减少动态效果偏好及键盘焦点样式。弹窗限制操作期间重复提交，删除确认优先提供Cancel；390px宽度下目标内容和按钮正常换行。

## 3. 后端实现和接口

沿用Controller → Service/ServiceImpl → Mapper/XML → MySQL；没有引入第三方依赖或更换版本。Controller继承现有BaseController，列表使用startPage/getDataTable/clearPage及TableDataInfo；其他操作使用AjaxResult。

| 方法与地址 | 参数/结果 |
|---|---|
| GET `/client/goals` | `current`、`pageSize`、可选`status=ACTIVE/COMPLETED`；返回`code/msg/rows/total` |
| GET `/client/goals/{id}` | 返回本人的目标详情 |
| POST `/client/goals` | `{title, details}`；返回新目标ID |
| PUT `/client/goals/{id}` | `{title, details, version}` |
| PUT `/client/goals/{id}/completion` | `{completed, version}` |
| DELETE `/client/goals/{id}?version=...` | 确认删除本人的指定版本目标 |

`version`来自列表或详情，不由前端自行计算。现有统一响应中的业务code用于表达400校验错误、401登录无效、403角色无权、404目标不可访问、409版本冲突，HTTP行为继续沿用现有全局处理。

权限为`goals:own`，仅授予student（role_id=10）。此外Service显式验证student角色，不能靠通配权限绕过。归属取自当前登录用户，不接受请求体中的studentId。详情及所有修改SQL都带student_id；修改/完成/删除同时带version并原子执行。不存在及他人的目标都返回相同不可用提示，避免透露归属。两个页面同时编辑只有一个成功，另一方得到409。

现有登录通道分离：导师/管理员的管理端token调用`/client/goals`会因通道不匹配得到业务401；另有Service单元测试覆盖带通配权限的非学生角色拒绝。前端菜单隐藏和路由守卫只是体验控制，不能替代后端验证。
