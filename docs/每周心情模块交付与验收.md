本轮按用户确认实现每周心情、个人历史/趋势、当前课程导师只读查看、私人备注隔离与首次告知确认。继续沿用六模块 Java 单体、现有登录/JWT/Redis、Controller → Service → Mapper/XML、BaseController、AjaxResult/TableDataInfo 和 Flyway。后端及前端依赖版本不变，参考项目只读。本轮没有提交或推送 GitHub，也没有重新生成旧迁移快照。

## 1. 启动和体验

1. 双击 `open-vscode.cmd`，打开生成的 `.local/up-self.code-workspace`，等待 Java 导入完成。
2. 电脑重启后先运行 VS Code 任务 **UP-SELF: 启动数据库与Redis**。
3. 选择 **UP-SELF · Backend + Frontend**，按 F5。不要同时运行另一份后端或 Vite。
4. 打开 **http://127.0.0.1:5173/**。账号密码仍在 `config/application-local.yml`，未修改现有密码。
5. 新代码首次启动由 Flyway 执行 V5；之后启动校验已执行迁移，不重复建表。新电脑空库仍按跨电脑教程先建立数据库和账号，再由应用初始化。

| 身份 | 入口 | 本轮操作 |
|---|---|---|
| Student / student01 | My mood；`/#/student/mood` | 首次阅读告知并确认，选择本周心情、可选私人备注、保存，查看本人历史和变化趋势 |
| Mentor / mentor01 | Student mood；`/#/mentor/mood` | 搜索/分页选择当前课程学生，只读查看心情与趋势，不读取备注 |
| Administrator / admin01 | 原 Administration | 继续账号和课程分配；没有心情菜单，直接调用相关 API 也被拒绝 |
| maintenance | 内部维护入口 | 不增加心情读取或代填能力；通配权限也不能绕过业务角色检查 |

**新账号没有假历史。** 完成首次确认并保存本周记录后才会出现第一条数据。趋势随着真实周记录累积；未填写的周为 No record，线条不跨空缺周。验收截图使用临时测试账号和历史日期数据，测试结束后已清理。

## 2. 用户已确认的权限规则

- 学生读取和记录自己的心情。每人每周一条；学生不能通过传入其他 studentId 切换记录归属。
- 当前负责学生**已加入且已发布**课程的导师，默认只读查看该学生的心情、历史和趋势。一个学生有多个当前导师时，这些导师均可查看；列表去重。
- 同一学生的心情是全局每周记录，不按课程重复记录。当前符合关系的导师可查看历史，包括较早周的记录。页面首次告知包含 history，并说明课程/导师变化会改变可见人。
- 私人备注仅学生本人读取。导师使用独立的公开投影类型，SQL 不选择 `private_note`，响应里没有 `privateNote` 键。
- 管理员和内部维护均不能通过应用接口读取心情内容、读取备注或代学生记录。
- 学生退出课程、导师被替换、课程变为草稿/归档或失效后，后续请求重新查询当前关系；失去最后一个有效课程关系的导师被拒绝。学生自己的历史仍保留。
- 若仍存在另一门有效课程关系，同一导师继续拥有只读访问，不因退出其中一门课程而错误撤权。

此规则替换旧计划中“学生单独向指定导师主动分享/撤销”的待开发方案。本期不用每周重复分享按钮。应用账号权限与数据库运维权限是两个层面；数据库及备份仍沿用现有的保管方式。

## 3. 首次告知与周记录规则

**首次使用：** 展示谁可查看、私人备注不可共享、课程/导师变化的影响，并列出当前导师。无导师时明确显示 Only you can view your mood right now，同时告知未来有效课程导师的范围。勾选 **I understand who can see my mood.** 才能继续。Not now 返回首页，不影响学习或作业。

服务端保存告知版本 `2026-10-22-v1` 与确认时间；未确认、否定确认和旧版本确认不能绕过校验直接提交。重复确认同版本不会重写确认时间。未来变更告知版本需要重新确认，旧确认不会自动授权新规则。

**每周：** `Asia/Kuala_Lumpur`，周一 00:00 到下周一 00:00 前，边界由服务端确定。数据库保存当地周一日期作为周标识，避免跨年周号重复。

- 选择 Very low / Low / In between / Good / Very good，无预选，文字配系统 emoji；选择不依赖颜色。
- 备注可空，最多 2,000 字符，界面通过普通文本显示，不执行 HTML。
- 明确 Save this week’s mood 和保存确认；没有自动提交心情。
- 本 MVP 保存后不修改或删除本周记录，页面在提交前说明此规则。下周可再次记录。
- 不允许客户端补填过去周、提前提交未来周。同周重复或并发请求只有一次成功，其余返回 409。
- 记录自愿；空缺周不补成中性、不推测心情、不计失败或排名，不生成诊断或自动预警。

## 4. 学生端的 inclusive 实现

沿用全站英文 i18n、字号、高对比、减少动态效果与键盘焦点规则。原生 fieldset/legend/radio 配清晰标签，备注有说明与长度限制，未保存离开时确认。

趋势默认最近 12 周，可切换 4/12/26/52 周；图表和表格可切换，改变时间范围会保留当前查看方式。每个实际记录有点，只有相邻且有记录的周连线。无记录显示 No record，日期标签由后端周标识计算。SVG 有标题、说明和点提示，表格提供文字替代；窄屏图表在内部滚动，页面本身不横向溢出。

历史和导师学生列表复用原分页组件。加载、空状态、权限错误、网络重试、提交失败均有英文提示。导师只读页面没有心情输入或私人备注控件。

## 6. 数据与事务

`mood_notice_ack`：student_id 主键、notice_version、accepted_at，关联 sys_user。

`mood_entry`：id、student_id、week_start、mood_level、private_note、create_time；`UNIQUE(student_id, week_start)`；关联已有确认记录。新表 utf8mb4 支持备注中的系统 emoji。原 V1～V4 和既有表结构保持不变。

确认和保存使用现有 Spring 事务。作业模块已采用的 READ_COMMITTED 读取方式在这里继续使用；保存时锁定有效学生行，重新校验告知、当前周和已存在记录，再插入。行锁和数据库唯一约束共同防止并发重复。没有修改全局隔离级别。

分页前完成需要额外数据库查询的授权；分页查询本身也包含当前关系和确认版本条件，防止授权后关系变化导致泄露。每次查询实时检查当前课程关系，不缓存导师心情访问范围。日志审计仅保存动作、记录 ID/告知版本和结果，不保存心情内容或私人备注。

迁移只能追加新版本，已经执行的 V5 不再编辑。新电脑按跨电脑教程恢复数据库；旧快照恢复后由 Flyway 增量执行缺少的迁移。旧快照不包含之后新增的真实心情记录，迁移现有数据需要重新备份数据库。本功能没有新增上传文件。

## 7. 实际接口

学生使用 `/client/moods`，导师使用 `/moods`，沿用现有通道 token 校验与前端 `/api` 代理。Controller 同时映射两个前缀，Service 仍精确检查业务角色与数据范围。

| 方法与路径 | 说明 / 权限 |
|---|---|
| GET `/client/moods/current` | 本周范围、确认版本/状态、当前查看者、本人本周记录；`mood:own:read` |
| POST `/client/moods/acknowledgment` | `{noticeVersion, accepted:true}`；`mood:own:record` |
| POST `/client/moods/entries` | `{weekStart, moodLevel, privateNote}`；服务端取本人 ID；`mood:own:record` |
| GET `/client/moods/history?current=1&pageSize=10` | 本人含备注的分页历史；`mood:own:read` |
| GET `/client/moods/trend?weeks=12` | 本人趋势，明确 null 空缺；`mood:own:read` |
| GET `/moods/students?keyword=...&current=1&pageSize=10` | 当前有关系的有效学生，去重分页；`mood:students:read` |
| GET `/moods/students/{id}` | 范围内学生姓名与账号；`mood:students:read` |
| GET `/moods/students/{id}/history` | 导师仅周和心情的分页历史；`mood:students:read` |
| GET `/moods/students/{id}/trend?weeks=12` | 导师同样不含备注的趋势；`mood:students:read` |

普通返回沿用 AjaxResult；分页沿用 BaseController 的 startPage/getDataTable/clearPage，顶层 `code/msg/rows/total`。现有 HTTP/业务 code 处理不变。非法输入 400、未认证 401、无权限/未确认 403、重复周或过期周 409。
