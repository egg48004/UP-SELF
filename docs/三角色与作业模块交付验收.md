## 1. 启动与体验

1. 双击项目根目录 `open-vscode.cmd`，使用生成的 `.local/up-self.code-workspace`。根目录同名文件是跨电脑共享模板。
2. 电脑重启后先运行 VS Code 任务 **UP-SELF: 启动数据库与Redis**。
3. 等 Java 导入完成，选择 **UP-SELF · Backend + Frontend**，按 F5。不要同时运行旧 `start.cmd` 或第二份 Vite。
4. 访问 **http://127.0.0.1:5173/**。后端 8080 根页保留历史账号测试页，日常使用 Vue 页面。
5. 密码仍在 `config/application-local.yml` 的 `bootstrap.passwords`；它们是初始化密码，用户自己改密后不会自动回写。
6. 新代码首次启动会由 Flyway 自动执行 V4；后续启动只校验，不重复建表。当前空库需先按跨电脑教程建立库和数据库账号。已有库正常增量迁移，不能重新导入旧快照覆盖新作业。

| 身份 | 入口与首页 | 菜单与职责 |
|---|---|---|
| Student / student01 | 公开登录页选择 Student；`/#/student/home` | My learning、My courses、Assignments、Reading settings；查看自己的课程、作业与反馈 |

维护入口隐藏只是界面安排；安全仍由原登录、接口权限和 Service 数据范围校验实现。管理员和维护均没有作业批改界面；维护通配权限也不能绕过作业 Service 的角色限制。

## 2. 使用步骤与真实规则

**管理员：** Course allocation → Create course → Assign mentor → Add student → Publish。可管理课程及账号；不会出现学生作业正文或代导师批改入口。

**导师：** Assignments → New assignment → 搜索/选择自己负责的课程 → 填标题、What to do、可选截止时间、Maximum score → Draft 或 Published → Save assignment。课程工作区也有 Teaching assignments 链接。可修改和归档作业，归档会对学生隐藏；为保护已有提交，本 MVP 不提供物理删除作业。归档课程不可再修改作业或批改。

**学生：** My assignments 或课程内入口 → Open assignment → 填文字/上传文件 → Save draft 或等待 30 秒自动保存 → Submit my work → 确认。上传不等于提交。已提交后不能直接覆盖；Check for feedback 查看导师结果。导师 Ask for changes 后可重新编辑和提交，旧尝试仍保留。

**批改：** 导师打开作业 → Review work → 下载已提交附件并阅读内容 → 输入分数与必填评语，或选择 Ask for changes → Send feedback。反馈立即对该学生可见。评分必须在该次提交的满分范围内；后续调整作业满分不会改变旧尝试的满分。

- 学生只见已加入且已发布课程中的 Published 作业。其他学生的正文、附件和反馈不可访问。
- 导师只见当前负责课程。转交导师后旧导师失去访问；学生被移除后立即失去对应课程作业及附件访问。
- 草稿仅本人可见。导师列表不返回未正式提交的草稿，历史提交退回后的新草稿也不泄露给导师。
- 允许晚交，服务端标记 Late submission。截止时间显示为 Malaysia / UTC+08:00，不做倒计时或惩罚排名。
- 每次尝试最多 5 个附件，每个最多 20 MB；PDF / DOCX / PNG / JPG / UTF-8 TXT。没有外部文件服务或额外中间件。
- 附件经登录请求下载，不是公开静态路径，不把 JWT 写进链接；文件强制 attachment，UUID 文件名、类型检查、大小限制。DOCX 检查容器条目/解压总量/宏文件，不解压到服务器。
- 草稿附件可移除；正式提交附件归入当次历史，不能覆盖或删除。重新提交需上传新的附件（如需要）。
- 支持错误重试、保留输入、提交确认、未保存离开提醒、上传进度/取消、30 秒草稿保存；并发改动返回 409 提示刷新，不静默覆盖。
- 全部界面提示英文；i18n 文案集中管理。学生使用短任务说明、文字加少量系统 emoji、清晰状态、键盘焦点及原阅读设置；没有自动播放、闪烁、成绩排名或仅靠颜色辨认状态。

## 4. 数据、事务和 Flyway

- `assignment`：课程、说明、发布状态、截止、满分、语言、乐观版本。
- `assignment_submission`：每人每作业唯一当前状态与版本。
- `assignment_attempt`：每次正式提交的答案、附件归属、时间、迟交、当次满分、反馈；提交序号与请求键分别唯一。
- `assignment_file`：私有存储键、文件元数据、当前草稿或历史尝试归属。

V4 已在本机成功执行；V1～V3 保持不变。新表 utf8mb4 支持学生的系统 emoji。不要修改任何已经执行的迁移；后续变更追加 V5+。数据库独立于参考项目。

写入按课程 → 作业 → 学生提交的顺序加行锁，再校验 version。作业写事务显式采用 READ_COMMITTED：实测 MySQL REPEATABLE_READ 下，事务在等课程锁之前已建立旧快照，同一请求的第二次提交可能无法看到刚插入的尝试；此设置让锁后查询读取最新提交。它只作用于作业写方法，不修改全局数据源隔离级别。唯一约束和同一 requestKey 返回已有结果共同保证重复提交不会生成第二条尝试。

事务回滚时清理本次新写文件，草稿文件移除在提交后清理物理文件；先鉴权再落盘。磁盘与数据库仍需一起备份，不能只复制数据库。应用崩溃可能留下无引用文件，本期未加定时清理基础设施；不影响已有附件读取。

跨电脑恢复旧 V1～V3 快照后，新应用会增量执行 V4。新作业数据和 `.local/uploads/assignments` 不在旧快照中；要迁移本轮之后产生的数据，应按跨电脑教程重新导出数据库并一起备份整个 `.local/uploads`。不要向已产生作业的库盲目恢复旧快照。

## 5. 接口契约

导师前缀 `/assignments`；学生前缀 `/client/assignments`。同一 Controller 映射，原 Security 按通道校验 token，Service 再校验角色及课程归属。前端统一加 `/api` 代理。

| 方法与相对路径 | 操作/权限 |
|---|---|
| GET `/` | 作业列表，`assignment:read`，数据范围限制；keyword/courseId/pending/current/pageSize |
| POST `/` | 导师创建，`assignment:edit` |
| GET / PUT `/{id}` | 读取 / 导师更新；更新携带 courseId、version |
| GET / PUT `/{id}/submission` | 学生读取 / 保存本人草稿，`assignment:submit` |
| POST `/{id}/files` | multipart file + version，学生草稿上传 |
| DELETE `/{id}/files/{fileId}?version=...` | 学生移除本人草稿附件 |
| POST `/{id}/submit` | version、assignmentVersion、answerText、requestKey；原子正式提交 |
| GET `/{id}/submissions` | 导师分页查看已提交学生，`assignment:review` |
| GET `/{id}/submissions/{submissionId}` | 导师查看正式提交历史 |
| POST `/{id}/submissions/{submissionId}/review` | version、decision=GRADED/RETURNED、score、feedback |
| GET `/files/{fileId}/content` | 权限与归属检查后的真实文件下载 |

业务 400/401/403/404/409 继续走原异常体系，前端识别业务 code，不能只看 HTTP 200。
